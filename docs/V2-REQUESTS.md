# requests for the artcoins v2 work session

collected while porting the credits engine to v2 (first against v2 commit 87a7522). the status column is checked against v2 commit d4aa46b (branch v2-legibility, decisions D76 to D81 in its docs/v2/DECISIONS.md). the engine tests run on the vendored build of d4aa46b (test/v2-artifacts/README.md). nothing here is done in this repo.

| # | request | why | status on d4aa46b |
|---|---|---|---|
| 1 | a pool's fee recipient (the bounty recipient) must be changeable after launch. decide who may change it (the coin admin, or the current recipient handing over) and whether it can be locked | the owner expects this and v2 has no setter: the hook stores the recipient at launch (`ArtCoinsHookV2` reads `cfg.bountyRecipient`, no write path), and the v1 locker's `updateRewardRecipient` is gone too. the engine works around it with its own router | met (D76 1). the coin admin repoints the hook bounty recipient with `setBountyRecipient(poolId, recipient)` and a locker reward recipient with `setRewardRecipient(coin, index, recipient)`, the protocol slot excluded, until `lockRecipients()` on the coin. renouncing the admin freezes both. `test/V2Stack.t.sol` covers both setters and the lock |
| 2 | rethink the minimum lp fee (D53). allow 0 without a global owner toggle, or drop the rule | the engine launches with lp fee 0 and a pure skim. the minimum exists only to keep the protocol's locker slot from being worthless; the protocol already has a floor on the skim (D52), which pays in eth with no collect and no conversion | met (D76 2, D77 3). `minLpFee`, its setter and its error are removed. a launch needs an lp fee or a baseline skim above 0 (`ZeroFeeLaunch`). the engine launches with lp fee 0 and the only factory owner command left is `setMinProtocolSkimShareBps(362)` |
| 3 | docs/v2/STATUS.md quotes contract sizes that do not match the commit (hook 15,741 built against 16,716 quoted, deployer 15,536 against 21,166, factory 19,771 against 20,424, ci profile) | a deploy check that compares sizes would compare against stale numbers | open. docs/v2/STATUS.md quotes hook 16,716 (rows 15 and 28) and hook 16,244, factory 19,423, locker 15,435, token 9,552, deployer 15,551 (row 123); the foundry.toml ci comment quotes hook 16,716. the d4aa46b build at the ci profile gives hook 16,170, factory 19,272, locker 15,482, token 9,154, deployer 14,665 |
| 4 | D73 says permit2, the universal router, the fee swapper and the burn router are seeded into a restricted coin's allowlist. the source seeds none of them | doc and code disagree | met (D76 4). the factory seeds only the owner `defaultAllowed` set, the locker, the escrow, launch extensions and the launcher's list. permit2, the universal router, the fee swapper and the burn router are not seeded |
| 5 | the hook exposes a push gas tunable (`PUSH_GAS_DEFAULT` 50,000, `setDeliveryParams`) but pushes the bounty leg with `_PUSH_GAS = 0` | the setting does nothing for that leg | met (D76 3). `pushGas`, `streamGas`, `streamMin` and `setDeliveryParams` are removed. the fee legs push with a zero gas call |
| 6 | docs/v2/CREDITS-ENGINE-INTERFACE.md is stale: tax sink, tax exemption and venue text (gone with D73), "skim refund rides the return delta" (the source credits the escrow), and the interface files lack `minLpFee`, `setMinLpFee`, `setTokenDeployer` | integrators read it first | met. the interface files declare `setTokenDeployer` and every external member, `minLpFee` and `setMinLpFee` are gone, and the stale tax and venue text is gone from docs/v2/CREDITS-ENGINE-INTERFACE.md |
| 7 | document that the anti sniper excess above the baseline skim goes entirely to the bounty recipient (a 1 eth buy in the window paid 0.89 eth to it in the fork test) | not stated anywhere a launcher would look | met. the hook header states the split: the bounty leg is the baseline skim times `bountyBps` plus all of the skim above the baseline |
