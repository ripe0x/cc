# independent review: the v2 port of the credits engine

this review quotes the launch split of its time (bountyBps 9_000, payeePpm 161_031). the current launch split is bountyBps 9_638 and payeePpm 112_778, FLOW 10.9.

reviewer did not write the port. scope: `git diff 0a44fdf HEAD -- src/ script/` (Core, CoreLib, FeeRouter, the generated interfaces, the launch scripts), read against docs/FLOW.md section 10 and the v2 source at commit 87a7522. the owner has full instant control of settings, controller, exitModule, targets and the router engine (FLOW 9.4, 10.2): "the owner can do X" is not a finding here. proof tests are in `test/ReviewV2Port.t.sol` and the suites named in the table. the review first wrote `test_FINDING_*` (the defect as it behaved) and `test_OK_*` (a property that holds). after the director's decisions the findings that were fixed carry `test_FIXED_*` proofs, the accepted ones `test_ACCEPTED_*`. all fork tests, real contracts, the only added code is attacker contracts.

status after the director's decisions: V2R-1, V2R-2, V2R-4, V2R-5, V2R-7 and V2R-8 fixed, V2R-3 and V2R-6 accepted. the table below is the review as written (findings, original proofs and suggested fixes); the status table after it says what was done and which test proves it.

result: no critical or high finding. one medium, one low, the rest are infos and process notes. the money path held: the router cannot be bricked or redirected by a non owner, the Core books only the router, doors pay last, and the reimbursement can never pass its cap.

## reimbursement question (the 1 wei carried from the external audit)

verdict: the Core cannot pay more than its cap, not even by 1 wei. only a mirror that rounds up (or divides once where the Core divides twice) can see one wei more.

arithmetic, `Core._repay`:

* `r = min( floor(G * basefee * reimburseBps / 10000), floor(cap * reimburseCapBps / 10000), ethPot )`
* G is the gas counted: `gasStart - gasleft() + 50000` (plus 350000 for the listing on the eth lane compose), cut at 1,500,000 on exit.
* eth lane compose: `cap = P`, the sum of the pulled costs, before the reimbursement is added; the stored statement cost is `S = P + r` afterwards. `r <= floor(P*C/10000) <= P*C/10000`, so `r*10000 <= P*C <= S*C`: below the cap of the pre cost and of the stored cost.
* exit of an eth lane statement: `cap = S` as stored (read into memory before any change). exit lane: `cap = floor(80 * avgScore * RATE_START / 1e4)` and then the second floor by `C`. one division instead of two gives a cap at least as large, never smaller.
* every term is a floor and the result is their minimum, so `r` is at most each exact quotient. no term is rounded up, no later step adds to `r`.
* example from the fork (`C = 333`): `P = 138444872072035132`, `P*C = 46102142399987698956`, quotient `4610214239998769.8956`. the Core paid `4610214239998769`. a ceiling mirror expects `...770`, one wei above what the Core allows itself.
* the other place a 1 wei or few wei gap can come from is the gas term: the invariant mirror measures gas around the external call, the Core measures inside, and a toolchain with another gas schedule moves that figure by a few units, which at a low basefee is a few wei. that is the test mirror, not the Core.

proofs: `ReviewReimburseTest.test_OK_ethLaneComposeNeverPaysAboveTheCapAndFloorsTheQuotient` (8 cap settings, cap binding, floor equality, strictness when the quotient is inexact), `testFuzz_OK_ethLaneAnyBasefeeAnyCap`, `test_OK_exitLaneAndEthLaneExitNeverPayAboveTheirCaps` (both exit cases, 500 gwei so the cap binds).

## notes per bullet

**FeeRouter.** `receive` is empty, no storage, no call, no log: nothing a sender controls changes its cost, and it fits 2,300 gas exactly (`FeeRouter.t.sol`, `test_OK_stipendPushReachesTheRouterTheCoreAndEveryStackSender` pushes from a contract with zero gas). if a future repricing made it dearer the hook falls back to an escrow credit that anyone claims into the router, so swaps never break. flush: reentry is blocked by `_busy` in flush and claim; the tip receiver has 50,000 gas and runs before the engine is paid, it can call `skim` or nothing useful. the caller cannot choose the destination: engine only, payees only from the owner list. forced eth (selfdestruct) in the router is forwarded as fees, booked once (`test_OK_forcedEthInTheRouterAndTheCoreIsBookedExactlyOnce`); forced eth in the Core waits for one `skim` and is not booked twice. engine unset: flush reverts, eth waits. engine that reverts or burns all gas: the call fails, the flush reverts whole, nothing is lost (V2PortMigration covers it). payee gas: a flusher cannot starve a payee while keeping the flush alive: the starved call burns its 63/64 and leaves too little for the engine call (`ReviewRouterGasTest`, sweep of 100,000 to 400,000 gas in 2,500 steps: no limit passes with the payee credited to `owed`). lock needs an engine, so it cannot strand eth; ownership is two step, a zero address clears the pending one.

**Core receive.** only `FEE_SOURCE` books, and only outside a measurement. flush from inside the payouts of compose, buyback (keeper tip) and `sellForEth` books on final state and leaves balance equal to pots (`ReviewFlushInPayoutTest`). the doors that call outside before final state (`buyListing`, `exitStatement`, `collectSales`) set the measuring flag: the only one where a stranger controls the callee is `buyListing`, hence V2R-1. exit and collect: the extra eth lands unbooked and `skim` books it once, no cost basis is read from it. receive and skim cannot double book: skim books balance above `ethPot + ethToBuyback` and receive adds the same amount to a pot in the same step. rounding of the fee split: `toBuyback` floors, the pot gets the rest, no wei is lost. checkpoint spam through flush moves the rate by rounding only (the climb is continuous compounding, error near 1e-15 per call).

**forbidden targets and the v2 addresses.** router, escrow, locker, hook, factory, pool manager, house, coin are refused by `addTarget`, so the Core can never be made to call `escrow.claimTo`, `setSelfClaimOnly` or the router as itself. the allowed set at launch is Seaport and CreditStrategy only; the others need an owner add. keeper, deployer, mev module, burn router, protocol controller are not listed (V2R-6) and grant the Core no right.

**v2 interaction.** escrow credits owed to the Core arise only from a partial fill refund of the Core's own swap (the hook credits `sender`, the Core, when hookData names no refund address); anyone claims them, the eth arrives from the escrow, is unbooked and goes whole to the pot by `skim` (same class as V2R-1 if claimed inside a measurement; needs a credit to exist, which cannot be produced on the launch pool). credits owed to the router (a failed stipend push) are claimed by anyone into the router and flushed by anyone. leftover allowance: V2R-3. the coin admin (the owner) unrestricting, locking or delisting the Core does not stop `buyback`: the take consumes the hook allowance when the Core is not listed; unrestricted, no allowance is needed; locked, the Core stays listed. donated coin is inert and `rescueCoin` is owner only. there is no swapper and no lp income at `lpFee` 0, so the convert sandwich question does not arise.

**launch package.** the coin address is `predictToken(sender, config)` with the sender in the salt: another account cannot take the address and with the factory deprecated cannot launch at all (`test_OK_onlyTheFactoryOwnerCanLaunchAndTheFactoryIsDeprecated`, ReviewPort `test_FIXED_launchHijackCannotTakeThePredictedCoin`). between the Core deploy and the launch nothing at the coin address can be bound: the only creator is the token deployer called by the factory. pool initialization and liquidity are one transaction, so no one acts between them. the house cannot be pre created for the predicted Core (`createAuctionHouse` binds to its caller). the coin address also depends on mutable factory state (default allowlist, hook escrow, token deployer): preflight checks the allowlist is empty and the escrow matches; a change by the factory owner between the simulation and the mined launch strands the Core (its `COIN` immutable would point at nothing) and postflight fails on `code: coin`; recovery is a new Core on the same router (`setEngine`) and `setAllowed` on the coin. config hash: covers every field of `LaunchConfig` (overrides included) except the derived fee source; mutation matrix reports 283 cases, 0 slips. postflight reads back every new field: bounty recipient, baseline, bounty bps, referral cap, lp fee, mev schedule, locker slots and protocol bps, restriction flag, allowlist (positive checks plus a negative list; the full list is not readable on chain), router engine, owner, payee, tip, split start, lock. resume reads the stage from chain, only sends what is missing, and keeps the owner's router changes behind `ROUTER_CHANGED` (a Resume run with that flag after a migration would set the engine back to the old Core: operator care, not a bug).

**size and determinism.** (as reviewed; after the V2R-1 and V2R-4 fixes the Core runtime is 24,501 bytes with 75 bytes of headroom and the FeeRouter 4,982) Core runtime 24,496 bytes, 80 bytes below 24,576, initcode 27,769 (limit 49,152); CoreLib 10,724; FeeRouter 4,970; ControllerV1 4,426. a clean rebuild of the four production contracts into a separate output directory with `--force` gave byte identical creation and runtime code (solc 0.8.30, via_ir, 200 runs, cancun, no metadata hash). `BuildIdentity` (4 tests) and `gen-interfaces.sh --check` pass. a different foundry version cannot change the bytes while solc and the settings are pinned; it is the pinned settings that matter, not forge.

## states the owner cannot recover from

* the pool's bounty recipient is the router and is frozen at launch: a router bug, a lost router owner key, or `lock()` with an engine that later needs replacing leaves the fee stream bound for good. `lock()` before `setSplitStart` also freezes a split that never starts.
* `owed` of a payee that can never accept eth stays in the router (no rescue path).
* a Core whose `COIN` is not the launched coin (see launch package above) is dead; the router and the coin admin can adopt a new Core.
* coin admin `renounceAdmin` or `lock` freezes the allowlist in its current state: harmless for the engine while the Core stays listed or the buyback relies on the hook allowance.
